本仓库采用纯 .env + process.env 的环境变量驱动配置方案，未引入任何第三方配置库（如 dotenv、config、conf），所有运行时参数通过顶层 server.mjs 启动时解析 .env 文件注入到进程环境，再由各模块直接读取。

## 1. 加载机制与入口
- 手动解析 .env：server.mjs 在启动阶段用正则逐行匹配 KEY=VALUE 写入 process.env，仅当目标键尚未存在时才覆盖，避免外部已设置值被覆盖。
- 开发热重启脚本 dev-restart.mjs 同样实现相同逻辑，确保 pnpm dev:restart 也能读取最新 .env。
- PM2 部署：ecosystem.config.cjs 中仅注入 NODE_ENV=production，其余环境变量由 PM2 自身管理或依赖宿主系统。

## 2. 配置项分类与约定
- 服务基础：PORT(3388)、BINANCE_TICKER_CACHE_TTL_SEC(60) — HTTP 端口、ticker 缓存 TTL。
- 代理网络：HTTPS_PROXY/HTTP_PROXY、NO_PROXY — 配合 --use-env-proxy 与 proxy-setup.mjs 的 curl 回退。
- 飞书推送：FEISHU_WEBHOOK、SMART_TREND_DECISION_WEBHOOK — 开关式：未设置则对应功能自动禁用。
- 扫描阈值：STABLE_MAX_DRAWDOWN(0.30)、LONG_MIN_SCORE(3)、DUMP_MIN_RISK(4) — 各扫描器策略参数。
- 监控标的：POSITION_HEALTH_WATCH_SYMBOLS、SMART_TREND_WATCH_SYMBOLS — 逗号/空格分隔，自动补全 USDT 后缀。
- 市值过滤：MAX_MARKET_CAP_USD(5e9)、MC_CACHE_LIMIT(200) — 排除大市值币种，CMC/CoinGecko 缓存条数。
- 外部 API：CMC_API_KEY、CMC_BASE — CoinMarketCap Pro Key，为空回退免费接口。

## 3. 架构与约定
- 单点加载、全局共享：.env 只在入口解析一次，后续所有模块通过 process.env.XXX || 'default' 取值，无集中配置对象。
- 布尔开关统一模式：xxx_ENABLED !== 'false' && !!WEBHOOK，即显式 false 才关闭，否则只要有 webhook 就启用。
- 数组/集合型配置：使用 split(/[,，\s]+/) 拆分后去空、大写化、补全后缀，再转为 Set 供高频查找。
- 数值型配置：全部经 parseInt/parseFloat 转换并带安全边界（如 Math.max(0, ...)）。
- 代理优先 curl：Windows + 有代理时 fetchJson 自动走 curl.exe --proxy，规避 Node fetch 代理不稳定问题。

## 4. 开发者应遵循的规则
1. 新增配置项一律以 process.env.XXX || '默认值' 形式声明，并在 README 的 .env 章节补充说明。
2. 不要引入新的配置格式（yaml/toml/json），保持单一 .env 源。
3. 敏感信息只放 .env，.gitignore 已忽略 .env；示例见 .env.example。
4. PM2 部署时如需额外环境变量，在 ecosystem.config.cjs 的 env 字段追加，或通过 PM2 的 --env-file / 系统级 env 注入。
5. 代理相关变量必须配合 node --use-env-proxy 启动参数使用，详见 package.json scripts。
